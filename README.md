# AWX Tower Installation Script for Ubuntu 24.04

Automated installation script for **AWX** (Open Source Ansible Tower) on Ubuntu 24.04 LTS using K3s (lightweight Kubernetes) and the AWX Operator. Includes optional Nginx reverse proxy setup for port-free access and SSL/TLS support.

## Overview

AWX is the open-source upstream project for Red Hat Ansible Tower (Ansible Automation Platform). It provides:
- Web-based UI for managing Ansible playbooks, inventories, and job scheduling
- REST API for automation integration
- Role-based access control (RBAC)
- Job scheduling and centralized logging
- Credential management and vault integration

## System Requirements

### Minimum Requirements
- **OS**: Ubuntu 24.04 LTS (64-bit)
- **CPU**: 2 cores (4+ recommended)
- **RAM**: 4 GB (8+ GB recommended)
- **Disk**: 20 GB free space (40+ GB recommended)
- **Network**: Internet connectivity required

### Recommended for Production
- **CPU**: 4+ cores
- **RAM**: 16 GB
- **Disk**: 100+ GB on SSD
- **Network**: Static IP address

## Quick Start

### Basic Installation

```bash
# Download the scripts
wget https://raw.githubusercontent.com/your-repo/install_awx.sh
wget https://raw.githubusercontent.com/your-repo/setup_nginx_proxy.sh
# or
curl -O https://raw.githubusercontent.com/your-repo/install_awx.sh
curl -O https://raw.githubusercontent.com/your-repo/setup_nginx_proxy.sh

# Make them executable
chmod +x install_awx.sh setup_nginx_proxy.sh

# Run main installation as root
sudo ./install_awx.sh
```

After installation (10-15 minutes), access AWX at:
- **Local access**: `http://localhost:30080` (from the Ubuntu host)
- **Network access**: `http://YOUR_SERVER_IP:30080` (from any machine on your LAN)
- Username: `admin`
- Password: (displayed at the end of installation)

> **Note**: The firewall is automatically configured to allow external access on port 30080. See [External Access](#external-access) for details.

### Optional: Access Without Port Number

To access AWX at `http://YOUR_SERVER_IP` (without `:30080`), set up a reverse proxy:

```bash
# Run after AWX installation
sudo ./setup_nginx_proxy.sh

# Or with HTTPS for production
sudo ./setup_nginx_proxy.sh \
  --domain awx.example.com \
  --email admin@example.com \
  --enable-ssl
```

See [Reverse Proxy Setup](#reverse-proxy-setup-optional) for full details.

## What Gets Installed?

The main installation script (`install_awx.sh`) performs the following:

1. **System Preparation**
   - Updates Ubuntu packages
   - Installs dependencies (curl, git, python3, kubectl, etc.)
   - Disables swap (Kubernetes requirement)
   - Configures firewall (UFW) for ports 22, 80, 443, 6443, 30080
     - Port 30080: AWX NodePort for external access

2. **K3s Installation**
   - Installs K3s (lightweight Kubernetes)
   - Configures kubectl access
   - Sets up kubeconfig at `/etc/rancher/k3s/k3s.yaml`

3. **AWX Operator Deployment**
   - Creates AWX namespace
   - Deploys AWX Operator
   - Waits for operator to be ready

4. **AWX Instance Creation**
   - Generates admin password (if not provided)
   - Creates AWX Custom Resource with:
     - NodePort service on port 30080
     - PostgreSQL database with 8 GB persistent storage (ReadWriteOnce)
     - Projects storage (ephemeral by default - see [Storage Considerations](#storage-considerations))
     - Resource limits for web, task, and execution environments
   - Deploys AWX instance

5. **Post-Installation**
   - Saves credentials to `/root/awx-credentials.txt`
   - Displays access information
   - Shows next steps

### Optional: Reverse Proxy Script

The repository also includes `setup_nginx_proxy.sh` for optional Nginx reverse proxy setup:
- Access AWX without port numbers: `http://server-ip`
- Enable HTTPS with Let's Encrypt SSL certificates
- WebSocket support for real-time updates
- Production-ready configuration

See [Reverse Proxy Setup](#reverse-proxy-setup-optional) section below for usage.

## Post-Installation Steps

After installation completes, follow these steps to configure AWX:

### 1. Access the Web Interface
Open your browser and navigate to:
```
http://YOUR_SERVER_IP:30080
```

Login with:
- Username: `admin`
- Password: (from installation output or `/root/awx-credentials.txt`)

### 2. Create an Organization
- Navigate to **Organizations** → **Add**
- Provide a name and description
- Save

### 3. Add Credentials
- Navigate to **Credentials** → **Add**
- Add various credential types:
  - **Machine**: SSH keys for managed hosts
  - **Source Control**: Git credentials for playbook repositories
  - **Cloud**: AWS, Azure, GCP credentials
  - **Vault**: Ansible Vault passwords

### 4. Create Inventories
- Navigate to **Inventories** → **Add** → **Inventory**
- Add hosts manually or import from dynamic sources
- Organize hosts into groups

### 5. Add Projects
- Navigate to **Projects** → **Add**
- Link to Git repositories containing your Ansible playbooks
- Configure SCM update options

### 6. Create Job Templates
- Navigate to **Templates** → **Add** → **Job Template**
- Select inventory, project, and playbook
- Configure variables, limits, and verbosity
- Save and launch!

## External Access

The installation script automatically configures AWX for external access from other machines on your local network (LAN).

### How It Works

AWX is exposed via **Kubernetes NodePort** service on port **30080**. The script:
1. Opens port 30080 in the UFW firewall
2. Configures the AWX service with type `NodePort`
3. Binds to all network interfaces (0.0.0.0), allowing external connections

### Accessing from Other Machines

**From any machine on the same network:**
```
http://<UBUNTU_HOST_IP>:30080
```

**To find your Ubuntu host's IP address:**
```bash
# On the Ubuntu host, run:
hostname -I

# Or:
ip addr show | grep "inet " | grep -v 127.0.0.1
```

### Verification

**On the Ubuntu host:**
```bash
# Check firewall rules
sudo ufw status | grep 30080
# Should show: 30080/tcp ALLOW Anywhere

# Verify service is exposed
kubectl get svc -n awx
# Should show: awx-service with TYPE=NodePort

# Check if port is listening
sudo netstat -tuln | grep 30080
# Should show: 0.0.0.0:30080 or :::30080
```

**From another machine on the network:**
```bash
# Test connectivity
curl -I http://<UBUNTU_HOST_IP>:30080
# Should return HTTP 200 or redirect

# Or open in browser:
# http://<UBUNTU_HOST_IP>:30080
```

### Custom Port Configuration

To use a different port, edit [awx.conf](awx.conf) before installation:
```bash
# Edit awx.conf
NODEPORT=32080

# Run installation
source awx.conf && sudo -E ./install_awx.sh
```

### Security Considerations

**For Local Network (LAN) Access:**
- Default configuration is suitable for trusted networks
- Uses HTTP (unencrypted) - acceptable for internal networks
- Firewall only allows specific port (30080), not full access

**For Internet/Production Access:**

If you need to expose AWX to the internet, consider these security enhancements:

1. **Use a reverse proxy with SSL/TLS** (Recommended):
```bash
# Use the provided Nginx reverse proxy script
sudo ./setup_nginx_proxy.sh \
  --domain awx.example.com \
  --email admin@example.com \
  --enable-ssl

# See "Reverse Proxy Setup" section for details
```

2. **Change from NodePort to LoadBalancer** (cloud environments):
```bash
# Edit awx.conf before installation
SERVICE_TYPE=LoadBalancer

# This requires cloud provider LoadBalancer support
```

3. **Additional firewall rules:**
```bash
# Restrict access to specific IP ranges
sudo ufw delete allow 30080/tcp
sudo ufw allow from 192.168.1.0/24 to any port 30080 proto tcp
```

4. **Use VPN** for remote access instead of exposing to internet

### Troubleshooting External Access

If you cannot access AWX from other machines:

1. **Verify firewall is open:**
```bash
sudo ufw status | grep 30080
```

2. **Check service exists:**
```bash
kubectl get svc awx-service -n awx
```

3. **Test from the host using external IP:**
```bash
curl -I http://$(hostname -I | awk '{print $1}'):30080
```

4. **See [TROUBLESHOOTING.md](TROUBLESHOOTING.md)** for detailed diagnostics, especially:
   - "Cannot access AWX from other machines on network (LAN)"
   - "AWX service not created"

## Reverse Proxy Setup (Optional)

By default, AWX is accessible on port 30080 (e.g., `http://server-ip:30080`). To access AWX without specifying a port number, you can set up **Nginx as a reverse proxy**.

### What is a Reverse Proxy?

A reverse proxy sits in front of AWX and forwards requests to it, allowing you to:
- Access AWX on standard HTTP port 80: `http://server-ip` (no port needed!)
- Enable HTTPS with SSL/TLS certificates
- Add an additional security layer
- Use custom domain names

### Quick Setup

We provide an automated script to set up Nginx reverse proxy:

```bash
# Basic HTTP setup (access via http://server-ip)
sudo ./setup_nginx_proxy.sh

# With custom AWX port
sudo ./setup_nginx_proxy.sh --awx-port 30080

# Enable HTTPS with Let's Encrypt
sudo ./setup_nginx_proxy.sh \
  --domain awx.example.com \
  --email admin@example.com \
  --enable-ssl
```

### What the Script Does

1. **Installs Nginx** (if not already installed)
2. **Configures reverse proxy** to forward port 80 → 30080
3. **Sets up WebSocket support** for real-time AWX job updates
4. **Configures firewall** to allow HTTP (80) and HTTPS (443)
5. **Optionally installs SSL** with automatic certificate renewal via Let's Encrypt
6. **Provides access URLs** and management commands

### After Setup

**Access AWX without port numbers:**
```
http://YOUR_SERVER_IP          # HTTP access
https://your-domain.com        # HTTPS access (if SSL enabled)
```

**Useful Nginx commands:**
```bash
# Check Nginx status
systemctl status nginx

# View access logs
tail -f /var/log/nginx/access.log

# View error logs
tail -f /var/log/nginx/error.log

# Test configuration
nginx -t

# Reload after config changes
systemctl reload nginx
```

### SSL/TLS Setup with Let's Encrypt

For production use, enable HTTPS with a free SSL certificate:

**Requirements:**
- A registered domain name
- Domain DNS pointing to your server's IP address
- Email address for certificate notifications

**Setup:**
```bash
sudo ./setup_nginx_proxy.sh \
  --domain awx.yourdomain.com \
  --email admin@yourdomain.com \
  --enable-ssl
```

**Certificate auto-renewal:**
Let's Encrypt certificates are automatically renewed by Certbot. Verify with:
```bash
# Check certificate status
certbot certificates

# Test renewal process
certbot renew --dry-run

# Manual renewal (if needed)
certbot renew
```

### Manual SSL Setup (Alternative)

If you prefer manual SSL configuration:

```bash
# Run basic setup first
sudo ./setup_nginx_proxy.sh

# Then add SSL with Certbot
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d awx.yourdomain.com
```

### Uninstalling the Reverse Proxy

To remove Nginx proxy configuration and restore direct port access:

```bash
sudo ./setup_nginx_proxy.sh --uninstall
```

This keeps AWX running and accessible at `http://server-ip:30080`.

### Configuration Files

| File | Description |
|------|-------------|
| `/etc/nginx/sites-available/awx` | Nginx configuration for AWX |
| `/etc/nginx/sites-enabled/awx` | Symlink to enabled site |
| `/var/log/nginx-awx-proxy.log` | Setup script log |
| `/root/awx-proxy-info.txt` | Access information |

### Reverse Proxy Options

```bash
Usage: ./setup_nginx_proxy.sh [OPTIONS]

Options:
  -h, --help              Display help message
  --domain DOMAIN         Domain name for AWX (optional, for SSL)
  --email EMAIL           Email for Let's Encrypt SSL certificates
  --enable-ssl            Enable HTTPS with Let's Encrypt
  --awx-port PORT         AWX NodePort (default: 30080)
  --uninstall             Remove Nginx reverse proxy configuration
  -v, --verbose           Enable verbose output
```

### Advanced: Custom Nginx Configuration

For custom configurations, edit `/etc/nginx/sites-available/awx`:

```nginx
# Example: Add custom headers
location / {
    proxy_pass http://localhost:30080;
    
    # Custom headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Strict-Transport-Security "max-age=31536000" always;
    
    # Increase timeout for long-running jobs
    proxy_read_timeout 3600s;
}
```

After editing, test and reload:
```bash
nginx -t
systemctl reload nginx
```

## Storage Considerations

### Default Storage Configuration

The installation uses **K3s local-path** storage provisioner with the following configuration:

- **PostgreSQL**: Persistent storage (8 GB, ReadWriteOnce) ✓
- **Projects**: **Ephemeral storage (emptyDir)** by default

### Why Projects Use Ephemeral Storage

AWX requires **ReadWriteMany (RWX)** access for the projects volume so both `awx-web` and `awx-task` pods can mount it simultaneously. However, K3s's `local-path` storage provisioner only supports **ReadWriteOnce (RWO)**, which allows mounting to only one pod at a time.

**Impact:**
- Projects data (Git repositories, playbooks) are stored temporarily in pod storage
- Projects are re-downloaded from Git on pod restarts (automatic)
- No data loss for Git-backed projects
- Suitable for most use cases where projects are version-controlled

### Enabling Persistent Projects Storage

To enable persistent projects storage, you need a **ReadWriteMany-capable storage class** such as NFS.

**Option 1: Use NFS Storage**

1. Set up NFS server and install NFS provisioner in K3s
2. Edit [awx.conf](awx.conf) before installation:
```bash
export PROJECTS_PERSISTENCE="true"
export PROJECTS_STORAGE_CLASS="nfs-client"  # Your NFS storage class name
export PROJECTS_STORAGE_SIZE="8Gi"
```

3. Run installation:
```bash
source awx.conf && sudo -E ./install_awx.sh
```

**Option 2: Modify Existing Installation**

```bash
# Edit AWX instance
kubectl edit awx awx -n awx

# Change these values:
spec:
  projects_persistence: true
  projects_storage_class: nfs-client  # Your RWX storage class
  projects_storage_size: 8Gi

# Wait for AWX to reconcile
kubectl get pods -n awx -w
```

### Storage Classes Comparison

| Storage Type | Access Mode | Use Case | Projects Storage |
|-------------|------------|----------|------------------|
| K3s local-path | RWO | Default, single-node | ❌ Ephemeral |
| NFS | RWX | Multi-node, persistent projects | ✓ Persistent |
| AWS EBS | RWO | Cloud, single-node | ❌ Ephemeral |
| AWS EFS | RWX | Cloud, persistent projects | ✓ Persistent |
| Azure Files | RWX | Cloud, persistent projects | ✓ Persistent |
| GCP Filestore | RWX | Cloud, persistent projects | ✓ Persistent |

### Checking Storage Status

```bash
# View storage classes
kubectl get storageclass

# View persistent volume claims
kubectl get pvc -n awx

# Check PVC details
kubectl describe pvc -n awx

# Check provisioner logs
kubectl logs -n kube-system -l app=local-path-provisioner
```

**See [TROUBLESHOOTING.md](TROUBLESHOOTING.md)** for NFS setup instructions and storage troubleshooting.

## Troubleshooting

### Installation Issues

**Problem: K3s fails to start**
```bash
# Check K3s service status
systemctl status k3s

# View K3s logs
journalctl -u k3s -f

# Restart K3s
systemctl restart k3s
```

**Problem: AWX pods not starting**
```bash
# Check pod status
kubectl get pods -n awx

# Describe pod for events
kubectl describe pod POD_NAME -n awx

# Check operator logs
kubectl logs deployment/awx-operator-controller-manager -n awx -f
```

**Problem: Cannot access web interface**
```bash
# Verify service is running
kubectl get svc awx-service -n awx

# Check if NodePort is accessible
netstat -tuln | grep 30080

# Check firewall
sudo ufw status
sudo ufw allow 30080/tcp
```

### Performance Issues

**Problem: AWX is slow**
- Increase resource limits in the AWX Custom Resource
- Add more CPU/RAM to the server
- Use external PostgreSQL database
- Check Kubernetes node resources: `kubectl top nodes`

### Database Issues

**Problem: PostgreSQL errors**
```bash
# Check PostgreSQL pod
kubectl get pods -n awx | grep postgres

# View PostgreSQL logs
kubectl logs awx-postgres-13-0 -n awx

# Access PostgreSQL
kubectl exec -it awx-postgres-13-0 -n awx -- psql -U awx
```

### Common Errors

**Error: "ErrImagePull" or "ImagePullBackOff"**
- Check internet connectivity
- Verify firewall allows egress traffic
- Check if container registry is accessible

**Error: "CrashLoopBackOff"**
- Check resource limits: `kubectl describe pod POD_NAME -n awx`
- Review pod logs: `kubectl logs POD_NAME -n awx`
- Verify persistent volume claims: `kubectl get pvc -n awx`

## Security Considerations

### Production Recommendations

1. **Use HTTPS/TLS**
   - Configure Kubernetes Ingress with cert-manager
   - Use Let's Encrypt for certificates

2. **External Database**
   - Use managed PostgreSQL (AWS RDS, Azure Database, etc.)
   - Enable SSL for database connections

3. **Authentication**
   - Configure LDAP/Active Directory
   - Enable SAML or OAuth for SSO
   - Enforce multi-factor authentication

4. **Network Security**
   - Use private networks
   - Restrict access with network policies
   - Use a VPN for remote access

5. **Regular Updates**
   - Keep AWX and operator updated
   - Update Ubuntu packages regularly
   - Monitor security advisories

6. **Backup Strategy**
   - Automated daily backups
   - Test restore procedures
   - Store backups off-site
